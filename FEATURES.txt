pcd FEATURES

PROJECT NAVIGATION

    Jump to a project by name:
        pcd <project>

    Show help (without opening the picker):
        pcd

    The interactive picker opens when a project query has multiple matches.
    Type to filter, use Up/Down to move, Enter to select, or Escape/Ctrl-C to cancel.
    Editing the query searches the entire cached catalog without scanning roots.
    The picker retains at most 100 results and displays 12 rows. Up/Down loads
    further windows, preserving access to all duplicate names. Clearing the query
    sorts by recency. Canceling leaves the current directory unchanged.

    Search ignores case and prefers exact names, then prefix, substring, and fuzzy
    matches. A unique exact name is selected directly. Equal text matches use
    last-used time and usage count as tie-breakers; duplicate names remain selectable.

    Resolve a project whose name conflicts with a command:
        pcd --project <project>
    This uses exact-name lookup only and cannot be combined with a subcommand.

    Directory changes require an active shell wrapper. Without it, pcd prints
    the destination and an integration hint instead of changing the parent shell.


PROJECT DISCOVERY

    Register the current directory as a scan root:
        pcd init

    Remove the current directory from scan roots:
        pcd uninit

    List registered scan roots:
        pcd roots

    Rescan roots, show added, removed, and total projects:
        pcd refresh

    Git repositories with a .git directory or worktree file are discovered when
    roots are registered, when the cache must be rebuilt, or after a search miss.
    There is no background watcher. A valid cache is reused by list and roots;
    use pcd refresh to force an update, including after manual config edits.

    Hidden directories are included by default; common dependency/build directory
    names are excluded. Scanning stops at a repository boundary. Symlinked trees
    are not followed by default, but a symlink directly to a repository is discovered.
    Configure scan.hidden, scan.follow_symlinks, and scan.exclude to change these rules.

    Refresh added/removed counts compare discovered project paths. The total includes
    manual projects. Missing manual registrations remain in the configuration.

    Root counts show how many discovered projects each root contributed, not how
    many canonical paths happen to be contained below it. A project is counted once
    in every root that discovered it, including overlapping roots and roots reached
    through followed symlinks. Manual projects are not counted.

    The cache records the root and display route for every discovery. Its file
    is now projects.sqlite3, with indexed exact/prefix lookup and a single metadata pass
    for fuzzy lookup. A valid schema-3 projects.jsonl is imported once, preserving
    its timestamp and provenance. Configuration and history retain their formats.
    Invalid snapshots are rebuilt; incomplete scans never replace a complete cache.
    Completion only reads the cache (or JSONL before migration); it never scans,
    migrates, loads history, or creates configuration. See docs/storage-030.rst
    for compatibility, recovery, and the cross-platform validation gate.

    Each cache snapshot records when its refresh began. If a newer refresh publishes
    while an older refresh is still scanning, the older refresh cannot overwrite the
    newer valid snapshot. A corrupt snapshot can be rebuilt.

    Configuration changes use read-modify-write locking, so concurrent root and manual
    project changes are not lost. Configuration changes and cache publication may run
    concurrently; an older scan cannot replace a newer published cache snapshot.

    If a filesystem error prevents a root, subdirectory, or .git marker from being
    inspected, the scan is incomplete. `pcd refresh` reports the failing path and leaves
    the last complete cache snapshot in place instead of publishing partial results.
    Missing roots are still skipped and handled as unavailable locations.


PROJECT REGISTRATION AND INSPECTION

    Register an existing directory manually, optionally with a custom name:
        pcd add [path] [--name <name>]
    Omitting path registers the current directory. A .git marker is not required.
    A path already known through a root or manual registration is not added again.

    Unregister a manual project or exclude a discovered checkout:
        pcd remove <project>
    Files stay on disk. Exclusions in config.toml apply to the canonical project
    across discovery routes and survive refresh. Add the path to restore it.

    Inspect metadata, availability and discovery routes for an exact name:
        pcd info <project>
    Both info and remove offer completion and duplicate-name selection.

    Diagnose the catalog and local setup without changing them:
        pcd doctor
    Missing roots, manual projects and stale exclusions remain in configuration.


PROJECT LIST

    List all known projects:
        pcd list

    Filter by source or availability, or print JSON:
        pcd list --manual
        pcd list --discovered
        pcd list --missing
        pcd list --json

    Combining --manual and --discovered includes both sources; --missing further
    restricts the result to unavailable directories. JSON contains name, path,
    source (manual/discovered), and status (available/missing). Table output labels
    discovered projects as scanned and may shorten home paths to ~; JSON preserves
    the full display path, including symlink routes.


CONFIGURATION

    Print the user configuration file path:
        pcd config path

    Print, edit, or validate the user configuration:
        pcd config show
        pcd config edit
        pcd config validate

    The top-level editor setting takes precedence over VISUAL, then EDITOR.
    For example, put `editor = "nvim"` before any TOML table header.
    config edit does not rescan projects: validate and refresh after editing scan roots,
    manual projects, or scan settings. Unknown keys, invalid types, duplicate paths,
    and relative config paths are rejected; absolute paths and ~ are supported.


USAGE HISTORY

    Successful project selection records last-used time and increments a usage count.
    History keeps up to 2,048 entries when written. Invalid history is treated as empty.
    If writing history fails with an I/O error, navigation continues and prints a
    warning to stderr. This history already exists; further ranking changes are planned.


DATA DURABILITY

    Configuration, usage history, and managed shell files use atomic replacement.
    SQLite publishes catalog refreshes in a transaction. Cache creation and
    recovery publish a complete replacement database.

    On Linux and macOS, the containing directory is synchronized after a successful
    replacement so the new directory entry survives a crash as far as the filesystem
    supports it. Windows does not support Python directory synchronization; file
    contents are still flushed and replacement remains atomic, but the directory
    entry is not separately synchronized.

    The benchmark suite reports the extra cost of parent-directory synchronization;
    see benchmarks/README.md.


SHELL INTEGRATION

    Supported platforms: Linux, macOS, and Windows.

    Supported shells:
        Bash
        Zsh
        Fish
        PowerShell 7+
        Windows PowerShell 5.1
        Command Prompt (cmd)
        Git Bash on Windows (using the Bash integration)

    Install shell integration automatically:
        pcd shell install [shell]

    CMD installation registers an exact DOSKEY command in the current user's AutoRun
    value without changing PATH or replacing unrelated AutoRun commands.

    Check shell integration status:
        pcd shell status [shell]

    Status reports the selected shell configuration and the wrapper used for this invocation.
    `Invoked through wrapper: no` does not mean the parent shell has no wrapper installed.
    A direct call such as `command pcd shell status` bypasses the wrapper.
    The wrapper marker is scoped to its function call, not exported for the whole shell session.

    Remove shell integration:
        pcd shell uninstall [shell]

    Print shell integration code:
        pcd shell init [shell]

    Shell names are bash, zsh, fish, pwsh, powershell, and cmd (Windows only).
    If omitted, the shell is detected. On Windows, install prompts when detection
    fails; other shell commands require an explicit choice in that situation.
    Install/uninstall preserve manual configuration and unrelated startup commands.
    Restart the shell or use the reload command printed by the installer.

    Windows PowerShell profile loading is subject to Execution Policy. Install and
    status check the selected PowerShell edition without loading its profile.
    Install refuses to edit profiles under Restricted or AllSigned, or if the check
    fails; status reports a warning. Policies are never changed automatically.
    A successful check does not validate the profile or guarantee another session's
    policy. See docs/windows.rst for PSSecurityException / UnauthorizedAccess and
    docs/troubleshooting.rst for other startup problems on Windows, Linux, and macOS.

    PowerShell managed startup blocks catch executable launch failures, warn, and
    let the rest of the profile load. Failed initialization output is not evaluated.
    App Control blocking pcd.exe is separate from Execution Policy blocking a .ps1
    profile; changing Execution Policy does not resolve an executable block.
    Existing managed blocks are updated by shell install; manual profiles must be
    updated by their owner. The CLI cannot run while its executable is blocked.
    See docs/windows.rst for diagnosis and docs/shells.rst for manual setup.

    Shell integration can also be added manually to the shell config.
    Version 0.2.3 removes `pcd shell print` and `pcd shell-init` and moves Python
    imports from `pcd_cli.shell_integration` to `pcd_cli.integrations.shell`.
    Old startup lines are not migrated automatically; see docs/shells.rst for replacement
    commands and reload instructions for Bash, Zsh, and Fish.
