PCD ROADMAP
===========

Current release: 0.2.8.

0.3.0 - EVERYDAY DIRECTORY NAVIGATION
-------------------------------------

Ship all four tasks together in 0.3.0. Keep the package at 0.2.8 during
development and bump it once when preparing the release.

    1. Remember ordinary cd visits. Offer opt-in shell tracking, honor path exclusions,
       and record each successful directory change once, including non-Git directories.
       Keep visits across sessions and cache rebuilds. An unchanged working directory
       should start zero extra processes at the next prompt.

    2. Search by multiple words. Match ordered path components so that "pcd acme api"
       finds the api checkout under acme. Rank ambiguous matches using visit frequency
       and recency. Preserve deterministic jumps for unique exact project names.

    3. Import zoxide history. Provide "pcd import zoxide --dry-run" to preview a merge.
       Preserve relative preferences and keep repeated imports idempotent.

    4. Resume work inside a project. "pcd PROJECT --resume" returns to the last
       visited subdirectory of that project. If it disappeared, explain why and open
       the project root. A plain "pcd PROJECT" continues to open the root.


REFRESH AND CACHE RECOVERY
--------------------------

    Refresh rebuilds the discovered project catalog from configured roots.
    Vanished discoveries drop out. Roots, manual registrations and exclusions
    survive even when their directories are temporarily unavailable.

    Preserve learned directories, visit counts and timestamps, preferences
    imported from zoxide, and each project's last visited subdirectory.
    Verify this by deleting the project cache, running pcd refresh twice,
    and checking that the same history, preferences and resume paths remain.


DIRECTORY SELECTION
-------------------

    pcd opens a unique exact project name directly, even when another directory
    has more visits. Duplicate exact names open the picker. For a partial or
    multi-word query, open a sole match directly and offer a picker for several.

    Rank by match quality, then frequency and recency; use the canonical path
    to break remaining ties consistently.

    Canceling the picker or finding no match keeps the current directory and
    history intact. Record a visit only after a successful directory change.


PLATFORM CHECKS AND RELEASE FOLLOW-UP
-------------------------------------

    The master test matrix passed on Linux, macOS and Windows at 9a1679c.
    Each Windows job (Python 3.12, 3.13 and 3.14) passed 639 tests, with no
    symlink tests among the 22 skips. The macOS job passed with system Bash.
    https://github.com/jestenough/pcd/actions/runs/44694333970

    CLI comparisons against v0.2.8, JSONL/SQLite storage comparisons and
    end-to-end shell jumps against zoxide 0.9.8 are complete on all three
    platforms. See docs/storage-030.rst for timings, disk use and memory.

    Before release, investigate full completion at 100k names (9–12% slower),
    wide refresh on Windows (8.6% slower), and the cost of full history reads.
    Profile exact shell jumps with two registered projects, including both
    resolution and post-change recording. PCD took 13–86 times as long as
    zoxide on this workload. Keep the package at 0.2.8 pending release review.

PROJECT ALIASES
---------------

COMMANDS
    pcd alias add <project> --as <alias>
    pcd alias remove <alias>
    pcd alias list

REQUIREMENTS
    Reference concrete project paths and survive `pcd refresh`.
    Detect conflicts with commands, projects, and other aliases.
    Show aliases in `pcd list` and `pcd info`.
    Report stale aliases in `pcd doctor`.
    Complete aliases in relevant commands.


PROJECT GROUPS
--------------

COMMANDS
    pcd group create <group>
    pcd group add <group> <project> [--as <member-name>]
    pcd group remove <group> <member-name>
    pcd group delete <group>
    pcd group list
    pcd group show <group>

NAVIGATION
    pcd <group>
    pcd <group>/<member-name>

REQUIREMENTS
    Use local member names and reference concrete project paths.
    Do not depend on parent directory names; survive `pcd refresh`.
    Allow the same member name in different groups.
    Resolve conflicts with commands, projects, and aliases deterministically.
    Keep `--project` available for explicit disambiguation.
    Complete group names and members; show groups in `pcd list` and `pcd info`.
    Report missing group members in `pcd doctor`.
    Preserve manual projects, aliases, and groups while rebuilding discovered projects.
    Remove missing discovered projects from the rebuilt cache, not user-defined references.
